## 백엔드 담당자에게 우선 전달할 질문

1. `POST /students` 및 `PATCH /students/{id}`가 필요한가요? 현재 웹 UI에 학생 추가·수정 버튼이 있습니다. 필요 없으면 프론트에서 제거하겠습니다.
2. `/dashboard/summary`의 실제 응답 예시(JSON)와 날짜·학년·반 필터 파라미터를 받을 수 있나요?
3. **전체 학생 대상** 학습/개념/오류/Tutor/게이미피케이션 통계는 어떤 API로 조회하나요? 현재 WEB-04~13은 학생별 경로입니다.
4. 반/기간/전체 리포트 및 PDF 파일 다운로드 API를 제공하나요? 생성·조회·다운로드 각각의 계약이 필요합니다.
5. 로그인/회원가입 요청 필드, JWT access/refresh 반환 형식, 역할별 접근 권한, 401 처리 규칙을 공유해 주세요.
6. 목록 API의 `page`, `size`, 검색어, 날짜 범위, 정렬 필드와 응답의 `items`/`content`/`total` 구조를 확정해 주세요.
7. 문제 일괄 등록 및 오개념 기준 데이터 관리는 별도 API가 필요한가요?
8. AI①·AI② 분석 결과는 WEB-08/09에서 어떤 형태로 전달되나요? 프론트는 내부 AI API를 직접 호출하지 않겠습니다.

## 현재 구현 수준 (2026-10-24)

- 화면: 기존 16개 화면 템플릿 재사용. 대부분 통계/차트/리포트 데이터는 **정적 샘플**.
- Axios: 인증·학생 목록/상세·학생별 분석 경로 및 개념/Skill/문제 관리 후보 경로 함수 준비. **응답 바인딩 미완료**.
- 학생 검색: 데모 목록의 이름 검색 동작. 날짜 조회는 입력 검증만 함.
- 학생 추가: Mock 모드 전용. 실서버 모드에서는 비활성화.
- 로그인: Mock 모드에서 데모 우회 허용. 실서버 모드에서는 데모 버튼 비활성화 및 미인증 화면 접근 차단. 실제 권한/토큰 갱신은 추가 협의 필요.
- 빌드/브라우저 통합 검증 결과는 별도로 확인 필요. API 명세서만으로 서버 기능이 완성되었다고 판단할 수 없음.
